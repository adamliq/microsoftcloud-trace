Deployment notes and prerequisites
  1. Source protocols: UDP/TCP 514 or TLS TCP 6514. SC4S uses HEC; Universal Forwarder uses S2S. rsyslog/syslog-ng can write files for forwarder collection.
  2. Requires Splunk Cloud 10.4.2604 or higher and an Ingest Processor Azure destination.
  3. Create a storage account with hierarchical namespace enabled, an export container, notification queue and dead-letter queue.
  4. Configure the Splunk Azure connection using an Entra application with Storage Blob Data Contributor. Set the dataset to Pipeline output and JSON.
  5. Route selected Linux syslog to the dataset. Configure a parallel Splunk indexing path if required.
  6. Inspect one exported file before defining JSON paths, DCR input types and timestamp conversion.
  7. Create the LinuxSyslog_CL table, DCE and DCR. Preserve the original message and timestamp.
  8. Deploy and customize the managed Sentinel Azure Storage Blob CCF connector, including its reader identity and Blob/Queue permissions.
  9. Configure Event Grid BlobCreated notifications for the export folder, pointing to the connector notification queue.
  10. Generate a test event and verify the blob, notification consumption and destination table. Monitor failures and duplicates.

Logical architecture only. Connections are illustrative; this POC does not connect to cloud services or deploy resources.
