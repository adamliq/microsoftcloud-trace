Architecture assumptions

Single-tenant workforce sign-in with Microsoft Entra ID. Azure App Service built-in authentication (Easy Auth), HTTPS, and server-directed login.

Inbound mode: Azure Firewall DNAT → Application Gateway/WAF → private endpoint → Web App. The Web App public endpoint is disabled. Requests, callbacks and responses use this ingress route.

Outbound mode: VNet integration + outbound application routing + UDR → the same Azure Firewall. Browser navigation to Entra itself remains outside the Azure application network.

App Proxy mode (alternative ingress): Microsoft Entra application proxy publishes the external URL and pre-authenticates users with Entra. A private network connector in vnet-web relays requests to the App Service private endpoint. Easy Auth still runs, completing its sign-in by single sign-on and using the external URL as its redirect URI. Front Door and inbound DNAT are turned off in this mode.

Resource groups are organisational scopes, not network isolation boundaries. This demo creates no Azure resources and accepts no credentials.
