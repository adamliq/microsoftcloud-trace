Source → category identifies generated logs; source → diagnostic setting identifies configuration ownership; category → setting enables routing. The setting targets a hub. The MSCS input reads that hub through a consumer group and assigns an index and sourcetype. The input runs on a collection host; that host’s forwarding configuration controls transport to Splunk. Preservation and enrichment contract
The simulation preserves each resource record as indexed _raw; verify actual add-on event breaking and serialisation before comparing real bytes. The demo calculates SHA-256 over the exact UTF-8 JSON string generated for each record. This digest identifies these bytes, not a signed chain of custody; reserialising JSON can change the digest. The custom event ID and trace ID are generated by this PoC, not Azure-native fields.
To retain lineage in a real collector, explicitly preserve or enrich the diagnostic-setting ID from configuration, Event Hub namespace/hub/partition/offset/sequence number, and records-array index. Namespace + hub + partition + offset + record index identifies the simulated delivery position. Consumer group identifies a reader view; checkpoint records progress and does not confirm successful Splunk indexing. Replayed messages can create duplicate indexed events.
The poc_ fields appear only when the optional custom-enrichment checkbox is enabled. They are a proposed enrichment contract. The stock add-on does not automatically guarantee these custom fields. Implement supported enrichment or maintain a separate lineage register linked to the event. Do not assume all resource records contain correlationId or caller identity. Producer correlation IDs, when present, correlate operations but need not uniquely identify each log event.

Microsoft Entra ID Metadata
Applications, devices, groups and users are periodic directory inventories retrieved from Microsoft Graph v1.0 over HTTPS by the Splunk Add-on for Microsoft Office 365. The default sourcetype is o365:metadata; this demo selects azure_poc as its index and the documented default polling interval of 86400 seconds.
Four individual inputs are shown for clarity; multiple types can also be selected in one input. Follow Graph paging and validate the actual source value, timestamp extraction and object splitting. Application objects are app registrations; service principals are a separate Graph collection. Group snapshots do not automatically enumerate members, and user snapshots do not constitute sign-in logs.
Lineage: tenant + object type + object id + collection run/time + Graph endpoint + input + index. Repeated object IDs represent successive snapshots, not duplicate audit IDs. Additional fields and queries can require extra Graph permissions. Grant application permissions and admin consent as required by the installed add-on integration guide.

Microsoft Defender for Cloud: continuous export
Configure export per subscription. On the Defender for Cloud resource menu, select Environment settings. Select the subscription that you want to configure data export for. In the resource menu under Settings, select Continuous export. On the Event hub tab, choose the data types (security alerts by severity, recommendations, security findings, secure score and controls, regulatory compliance), the export frequency (streaming updates, snapshots or both), and the target namespace, hub and an authorization rule with Send rights. If the namespace restricts network access, allow export as a trusted service. The configuration is stored as a Microsoft.Security/automations resource and can be deployed at scale with Azure Policy.
Continuous export sends what the enabled Defender plans produce. Enable plans under Environment settings › subscription › Defender plans; each is a Microsoft.Security/pricings setting. Choose the plan as the sample operation under Security alerts or Security findings, and use the Defender plan not enabled scenario to see that a disabled plan raises nothing to export.

Azure Virtual Desktop: host pool, workspace & session host logon
Host pool and workspace diagnostic settings export to azure-resource-logs and arrive as azure:monitor:resource. Connection, Checkpoint and Error records for one connection share a native CorrelationId; workspace Feed records show feed downloads. Entra sign-ins for Azure Virtual Desktop and the Remote Desktop single sign-on token use the existing Entra stream.
The session host Security log takes a different route: a Splunk Universal Forwarder on the session host reads WinEventLog://Security and forwards directly to the receiving tier as XmlWinEventLog, with field extraction from the Splunk Add-on for Microsoft Windows. There is no diagnostic setting, Event Hub or hf-poc on that route. Logon events 4624 and 4625 (logon type 10) do not carry the AVD CorrelationId, so correlate them by user, session host and time.

Real-environment validation
  1. Query the source resource’s supported diagnostic categories; enable the required category and feature logging. For storage, select the blob/file/queue/table child resource. Configure the diagnostic setting to the destination Event Hub.
  2. Set an appropriate retention window and consumer group; grant the collector’s Azure application Event Hubs Data Receiver access and configure networking for the selected transport.
  3. Configure the Microsoft Cloud Services add-on on a collection instance, typically a heavy forwarder, and configure forwarding to Splunk. This path uses the Event Hub input; HEC is not required.
  4. Verify record splitting, timestamp extraction and the actual add-on sourcetype. Resource logs use azure:monitor:resource; the Entra sign-in stream uses azure:monitor:aad. The generic input default is mscs:azure:eventhub. If implementing the proposed lineage contract, verify every poc_ field at each handoff and compare the preserved raw bytes.
  5. Generate an approved test event. Correlate resource ID, category, source time and available producer identifiers; validate Event Hub arrival, consumer health and a searchable Splunk event. Test replay and duplicates; restore collection before retention expires.
This demo covers resource diagnostic logs. The four requested Entra sign-in categories are now included as a tenant-level stream. Subscription Activity Log, metrics, other Entra categories, VM guest logs and AKS workload logs remain separate scopes. For Event Hub source diagnostics the demo routes to a different destination namespace; do not create a diagnostics feedback loop.
